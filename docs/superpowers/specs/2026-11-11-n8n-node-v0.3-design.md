# n8n-nodes-postsider 0.3.0: simple publishing, full coverage, trigger

Date: 2026-11-11. Owner asked for: Publish Now, all missing functions, a simpler node, modeled on what works in Postiz, Buffer, Late, Blotato and PostHog nodes.

## Why

0.2.3 is hard to use for the main job ("take this text and media, post it to these channels"):

- Post > Create offers only Draft and Schedule. No **Publish Now**.
- Each channel is a separate fixedCollection row with its own content, so posting one text to 4 channels means 4 rows.
- Media must be pasted as `Media JSON` (`[{id,path}]`) after a separate Import From URL step. No binary input from a previous node (Google Drive, HTTP Request, OpenAI image).
- Settings and tags are raw JSON.
- No Update, Delete, Duplicate, Upload file, Media library, Analytics, Channel rules, Publishing pause, Trigger.
- Approval, Policy and Group operations return **404 on production** (`api.postsider.com`, probed 2026-11-11): the control plane (approvals, policies, customers, webhook subscriptions, retry-failed, audit, organization) is merged to `main` but not deployed. They work on self-hosted builds from current `main`.

## Competitor findings (research 2026-11-11)

- Postiz (`n8n-nodes-postiz`): flat op list, Draft/Schedule/Now, but free-text channel IDs, key/value settings, manual two-step media upload. No trigger, no AI-tool flag. Copy the mode toggle; avoid the rest.
- Buffer (`@bufferapp/n8n-nodes-buffer`): one Create with a share mode (queue / next / custom), silently fixes invalid per-network combos.
- Late/Zernio: empty date = publish now; webhook registration resource; no trigger node.
- Blotato: platform picked first, only that platform's options shown; media from binary or URL inside the post flow; "next free slot" toggle; Get by id for async results.
- PostHog: tiny clean resource > operation surface.
- Nobody ships a dedicated trigger node or documents `usableAsTool`. Both are differentiators for us.

## Goals

1. Publishing in 4 visible fields: **Channels** (multi-select), **Text**, **Media**, **When** (Now default).
2. Media straight from binary data or URLs inside Publish; upload happens implicitly.
3. Cover every public API operation that exists on production, plus the control-plane ones (kept, labeled).
4. A **PostSider Trigger** node that works on production today.
5. Old workflows keep working unchanged.
6. Stay a verified-ready community node: no runtime dependencies, passes `npx @n8n/scan-community-package`, `n8n-node lint`, strict mode.

## Non-goals

- No per-platform operations (Late style). One Publish for all platforms.
- No backend changes in this work. Missing production routes are an owner deploy item.
- No webhook-based trigger yet (routes not on production). Polling only; webhook mode is a follow-up once `/webhook-subscriptions` is deployed.

## Anti-goals

- Anything that requires pasting `{id,path}` JSON for the common case.
- Breaking a saved 0.2.x workflow.
- Retrying a failed post by creating a duplicate (UNKNOWN_OUTCOME may already be live).

## Versioning (decided)

Node `version: [1, 2]`, `defaultVersion: 2`. Version 1 keeps today's exact parameters and behavior (`displayOptions.show['@version']: [1]`). New nodes get version 2. Package 0.3.0, CHANGELOG entry, README rewrite. Credential unchanged.

## Version 2 surface

Resources, in this order (operations alphabetical in the UI as n8n lint requires, default op noted):

### Post (default resource)
- **Publish** (default op, action "Publish a post"). Fields:
  - `Channels` multiOptions from `getChannels` (expressions allowed; also accepts a comma-separated id string from an expression).
  - `Text` string, multi-row, required.
  - `When` options: **Now** (default), **At a specific time** (shows `Date` dateTime), **Next free slot** (GET `/find-slot/:firstChannelId`, then schedule), **Save as draft**.
  - `Media` options: **None** (default), **From binary data** (shows `Binary Properties`, default `data`, comma separated, every listed property of the input item is uploaded with multipart `POST /upload` field `file`), **From URLs** (shows `Media URLs`, comma/newline separated, each via `POST /upload-from-url`), **Already uploaded** (shows `Media` JSON `[{id,path}]`, for power users and v1 parity). Upload results go into `value[0].image` of every channel.
  - `Options` collection (all optional): `First Comment`, `Per-Channel Text` (fixedCollection channel + text overriding Text for that channel), `Platform Settings` (see below), `Tags` (fixedCollection value/label), `Shorten Links` boolean, `Idempotency Key` (default derived as in v1), `Wait for Result` boolean (default false; for Now and next free slot), `Wait Timeout (Seconds)` (default 60, max 300).
  - Output: one item per created post row: `{ postId, group, channelId, channelName?, state, publishDate, releaseURL?, error?, approvalRequested?, policy? }`. With Wait for Result: poll `GET /posts/:id` every 5 s (n8n-workflow `sleep`) until every row is PUBLISHED or ERROR or timeout; timeout returns the last state with `timedOut: true`, never an error.
- **Get** (post id, Simplify) as v1.
- **Get Many**: `Range` options Next 7 days (default) / Last 7 days / Custom (start/end), filters `State` (any/QUEUE/PUBLISHED/ERROR/DRAFT), `Channel`, `Group`, `Return All`/`Limit` (client side over the response), Simplify.
- **Update**: post id + optional Text, Date, First Comment, Media (same media modes), Platform Settings. `PUT /posts/:id`, only sent fields.
- **Delete**: `DELETE /posts/:id` (deletes the whole group; description says so).
- **Duplicate**: `POST /posts/:id/duplicate` with optional channel and date.
- **Retry Failed**: `POST /posts/group/:group/retry-failed` (control plane; the description says "requires PostSider server 2026-11 or newer").
- **Check Content**: `POST /posts/check` (content, platforms, hasMedia) for limits validation before publishing.
- **Rewrite with AI**: `POST /posts/rewrite` (content, tone, count, platform).
- **Get Analytics**: `GET /analytics/post/:id?date=days`.

### Media
- **Upload**: binary property or URL (same helpers as Publish). Output `{id, path, ...}` ready for "Already uploaded".
- **Get Many**: `GET /media?page&search`.
- **Delete**: `DELETE /media/:id`.

### Channel
- **Get Many** (as v1, plus include disabled toggle).
- **Get Rules**: `GET /integration-settings/:id` (max length, required settings schema, rules text).
- **Find Next Slot**: `GET /find-slot/:id` (moved here from the Scheduling resource; v1 Scheduling stays for version 1).
- **Get Analytics**: `GET /analytics/:id?date=days`.
- **Enable / Disable**: `POST /integrations/:id/enable|disable`.

### Publishing
- **Get State** `GET /publishing/state`, **Pause** / **Resume** `POST /publishing/pause` (body as the backend expects; read the controller).

### Approval, Policy, Group (control plane)
Same operations as v1 version, each resource and operation description starts with "Requires PostSider server 2026-11 or newer". No behavior change.

### Platform Settings (decided shape)
A collection under Options with typed, optional fields for the providers that most often need settings, names taken exactly from the provider DTOs in `postsider/libraries/nestjs-libraries/src/dtos/posts/providers-settings/` (x, youtube, tiktok, instagram, pinterest, linkedin, reddit if present, facebook, dev.to/medium/hashnode title). Each field's description names its platform. The node puts a field into a channel's `settings` only when that channel's provider uses it (provider from `/integrations` `identifier`; fetch once per execution). Plus a `Settings (JSON)` escape hatch merged last, per channel id or global. `__type` is never sent (backend adds it).

## PostSider Trigger node (new)

`PostSiderTrigger`, polling (`polling: true`, `poll()`), credential `postSiderApi`, icon same. Events (multiOptions): **Post Published** (default), **Post Failed**, **Post Scheduled** (new QUEUE rows). Filters: Channels (optional). Each poll calls `GET /posts` for a window from the last poll time minus 1 hour to now plus 30 days (bounded), filters by state, dedupes by post id + state in `getWorkflowStaticData('node')` (keep at most 2000 ids). First activation stores the current set and emits nothing (manual mode returns the newest matching post so users can map fields). Output item per post, same simplified shape as Get. Later, when webhook subscriptions are on production, a webhook mode can be added without breaking this.

## AI agents

`usableAsTool: true` on the main node (already). Every v2 operation gets an `action` and a plain description written for an LLM ("Publishes text and optional media to one or more channels now, at a time, or in the next free slot").
